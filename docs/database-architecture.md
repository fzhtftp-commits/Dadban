# معماری دیتابیس دادبان

## هدف
این مرحله پایه ذخیره‌سازی واقعی موکل‌ها را آماده می‌کند. دیتابیس بر مبنای PostgreSQL طراحی شده و از ابتدا برای جداسازی اطلاعات دفترها، ثبت رویدادهای امنیتی و حذف نرم آماده است.

## جداول اصلی

### offices
اطلاعات دفتر وکالت. هر دفتر یک محدوده داده‌ای مستقل است.

### users
کاربران دفتر و نقش آن‌ها. اطلاعات احراز هویت حساس در این جدول نگهداری نمی‌شود و بعداً از سرویس احراز هویت امن استفاده خواهد شد.

### clients
اطلاعات موکل حقیقی و حقوقی.

موکل حقیقی:
- نام و نام خانوادگی
- کد ملی
- تاریخ تولد
- شغل

موکل حقوقی:
- نام شرکت
- شناسه ملی
- شماره ثبت

اطلاعات مشترک:
- موبایل
- تلفن
- ایمیل
- نحوه آشنایی
- آدرس
- یادداشت
- وضعیت

### audit_logs
ثبت عملیات حساس مانند ایجاد، ویرایش و حذف موکل و تغییرات امنیتی.

## اصول امنیتی
1. هر رکورد موکل به office_id متصل است.
2. کد ملی در سطح هر دفتر یکتا است.
3. شناسه ملی شرکت در سطح هر دفتر یکتا است.
4. رکوردها حذف فیزیکی نمی‌شوند؛ deleted_at برای حذف نرم استفاده می‌شود.
5. زمان‌ها با timestamptz و به صورت UTC ذخیره می‌شوند.
6. شناسه‌ها UUID هستند.
7. احراز هویت از اطلاعات تجاری جدا نگه داشته می‌شود.
8. دسترسی نهایی باید از سمت سرور کنترل شود.
9. پس از اتصال API، PostgreSQL Row Level Security برای جداسازی دفترها فعال می‌شود.
10. عملیات حساس در audit_logs ثبت می‌شوند.

## ترتیب پیاده‌سازی بعدی
1. ایجاد PostgreSQL واقعی
2. اجرای database/schema.sql
3. ساخت API امن برای clients
4. احراز هویت سمت سرور و تعیین office_id از session/token معتبر
5. اتصال صفحه ثبت موکل به API
6. اتصال لیست موکل‌ها به API
7. اتصال پروفایل به رکورد واقعی
8. فعال‌سازی ویرایش واقعی
9. حذف نرم + ثبت audit log
10. تست امنیتی و تست جداسازی داده دفترها

## نکته مهم
فعلاً هیچ رمز عبور، توکن، کلید API یا secret در این مخزن قرار نمی‌گیرد. اطلاعات اتصال دیتابیس نیز فقط باید در Secret/Environment سمت سرور نگهداری شود.
