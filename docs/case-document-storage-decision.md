# تصمیم معماری ذخیره‌سازی اسناد دادبان

**وضعیت: تصمیم مقدماتی؛ آپلود فایل غیرفعال است.**

## وضعیت فعلی

ماژول اسناد فقط فراداده را در PostgreSQL نگه می‌دارد. ستون `storage_status` فقط مقدار `metadata_only` را می‌پذیرد؛ API فعلی مسیر فایل، URL فایل، محتوای باینری یا لینک دانلود قبول نمی‌کند. این محدودیت عمدی است تا قبل از انتخاب محل ذخیره‌سازی، هیچ سند واقعی در فایل‌سیستم موقت یا فضای عمومی قرار نگیرد.

## محدودیت میزبانی فعلی

مستندات رسمی Render می‌گویند فایل‌سیستم سرویس به‌طور پیش‌فرض موقت است. در پلن رایگان Web Service، فایل‌های محلی هنگام restart، deploy یا spin-down از بین می‌روند و Persistent Disk پشتیبانی نمی‌شود. Persistent Disk برای سرویس‌های پولی قابل اتصال است، اما فقط در همان یک نمونه سرویس قابل دسترسی است و امکان scale کردن سرویس به چند instance را محدود می‌کند.

منابع:
- https://render.com/docs/free
- https://render.com/docs/disks
- https://render.com/docs/faq

**نتیجه:** ذخیره فایل پرونده در پوشه محلی سرویس Render رایگان قابل قبول نیست. در این PR هیچ تغییری در تنظیمات Render انجام نمی‌شود.

## معماری پیشنهادی پیش از فعال‌سازی آپلود

1. **ذخیره‌سازی خصوصی شیءگرا** (private object storage با API سازگار با S3) را برای محیطی که پشتیبان‌گیری و دوام داده دارد، ارزیابی کنیم؛ bucket عمومی یا URL دائمی در دیتابیس ممنوع باشد.
2. در PostgreSQL فقط metadata، شناسه تصادفی object، اندازه، MIME تشخیص‌داده‌شده، checksum، وضعیت اسکن و وضعیت چرخه‌عمر ذخیره شود. نام فایل ارسالی کاربر نباید مسیر ذخیره‌سازی را تعیین کند.
3. مرورگر فایل را فقط از طریق API احراز هویت‌شده و با CSRF و محدودیت اندازه/نوع ارسال کند، یا پس از طراحی جداگانه از URL امضاشده کوتاه‌عمر استفاده شود. هر بار دسترسی/دانلود باید مجدداً مالکیت دفتر و پرونده بررسی شود.
4. قبل از قابل دانلود شدن: تشخیص نوع فایل با محتوای واقعی نه صرفاً پسوند، محدودیت حجم، نام‌گذاری امن، قرنطینه و اسکن بدافزار، عدم اجرای فایل، کنترل MIME، ثبت audit، و سیاست حذف/نگهداری پیاده شود.
5. رمزنگاری در انتقال و در حالت سکون، مدیریت کلیدها خارج از GitHub، پشتیبان‌گیری و آزمون بازیابی، سقف هزینه/فضا، حذف همگام metadata و object و کنترل دسترسی اپراتورها بررسی شود.
6. تصمیم نهایی باید هزینه ماهانه، محل نگهداری داده، الزامات محرمانگی پرونده‌های حقوقی، سیاست پشتیبان‌گیری، محدودیت پهنای باند و امکان خروج/انتقال داده را مقایسه کند.

## دروازه تأیید

آپلود واقعی فقط پس از انتخاب صریح سرویس ذخیره‌سازی و تأیید هزینه/سیاست نگهداری، طراحی و بازبینی امنیتی جداگانه، و آزمون‌های دسترسی بین دفترها فعال خواهد شد. تا آن زمان UI و API فقط فراداده را مدیریت می‌کنند.
